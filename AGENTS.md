## Learned User Preferences

- Sign commits and pushes with the user's signing key (GPG on YubiKey).
- When the upstream updater rewrites an app, follow each file's existing style. In `CHANGELOG.md` only, leave a blank line and add `- Upgrading from upstream version <previous version> -> $APP_NEW_VERSION`, with the previous version written out and `$APP_NEW_VERSION` left for the updater script.
- When debugging UI login, setup wizards, auth providers, or “config change didn’t take,” check a private/incognito window (or hard-refresh) early before deep infrastructure digs — browser cache has already burned hours on false alarms (e.g. PatchMon local-auth wizard).
- When wrapping an upstream container as a Home Assistant app, prefer the upstream image's own `ENTRYPOINT`/`CMD` (export options as env, then `exec` that entrypoint). Only replace it when HA rules require something the upstream entrypoint cannot do (e.g. grafting s6 onto a scratch/static binary, or a custom wrapper that still ends in `exec` of upstream).
- Always ship an `apparmor.txt` with every Home Assistant app; never leave a new app without one.
- Always bump Home Assistant add-on `version` semantically when shipping wrapper-only fixes (e.g. `3.7.17-1`) so Supervisor re-pulls the image; Home Assistant does not redownload an unchanged version and does not purge quickly.
- Do not rewrite existing CHANGELOG history; changelogs are append-only. Leave a blank line and add new upgrade entries only.
- When testing new or changed Home Assistant apps, run them on the Supervised instance at `http://10.0.3.2:81` (`homez`; was `10.0.3.6`) before treating a fix as verified. Do not assume GHCR/CI alone is enough. Add-ons that need custom bind mounts or `SYS_ADMIN` require Protection mode off.
- On public GitHub repos, add the Buy Me a Coffee sponsorship link `buymeacoffee.com/charlestephen` via the standard GitHub Sponsors/funding metadata.
- Keep image CI path-filtered so only apps whose own paths change rebuild; a new or changed app must not force rebuilds of unrelated images.
- Prefer sparse comments in code; skip lengthy explanatory comments unless something is genuinely non-obvious.

## Learned Workspace Facts

- Every app ships a valid `apparmor.txt` whose `profile` name matches `config.yaml` `slug` exactly (hyphens included). Supervisor loads it from the repo; image rebuild is not required for profile-only changes, but `apparmor.txt` is in the build workflow path filter so related commits stay discoverable.

- Home Assistant displays `version` from each app's `config.yaml`. That field must be a real version. `.github/workflows/track-upstream.yml` runs `scripts/update-upstream-version.py --all` for every app with `upstream_repo` in `build.yaml`, then `scripts/push-github-signed-commit.py` commits through GitHub's `createCommitOnBranch` API with no custom author or committer so the commit is signed. `build.yml` builds images from `ghcr.io/hassio-addons/base:stable` after that push and refuses a version that still contains `$`.
- The updater strips a leading `v` from release tags and maps tags such as `REL-9_18` and `REL_18_6` to `9.18` and `18.6`. Sources that need the prefix keep it via `upstream_version_arg_prefix` or `upstream_build_from_prefix` (Alloy's download URL and Homarr's image tags). It ignores prerelease tags and will not replace a recorded version with an older one.
- `upstream_repo` is the version source and can differ from the published image: pgAdmin is `pgadmin-org/pgadmin4` (tags only; no GitHub Releases) with image `dpage/pgadmin4`; Technitium is `TechnitiumSoftware/DnsServer` with image `technitium/dns-server`; Traefik tracks `traefik/traefik`; Traefik Manager Agent is `chr0nzz/traefik-manager` with image `ghcr.io/chr0nzz/traefik-manager-agent`; Forgejo is `codeberg.org/forgejo/forgejo`; dockhand-hawser tracks `Finsys/hawser` (no Hawser version field in the HA config); Pocket ID tracks `pocket-id/pocket-id`; Homebridge tracks dated tags on `homebridge/docker-homebridge` (`homebridge/homebridge` image, host networking; Supervisor data mounts at `/homebridge` via `map.path` — not `/data/homebridge` bind+`SYS_ADMIN`; `/ssl` for optional HTTPS; in-container Avahi defaults off with `host_dbus` because the HA host already runs mDNS; UI backup restore reinstalls plugins via npm — if the UI wedges after the last plugin, restart the add-on); Ultimate CA Manager tracks `NeySlim/ultimate-ca-manager` (`neyslim/ultimate-ca-manager`, runs as root, PKI under `/ssl/ucm/`). PostgreSQL tracks `postgres/postgres` tags `REL_18_*` only. Tang tracks `latchset/tang`. Resolved Watchdog is first-party and has no upstream release.
- Updates compare `upstream_version.txt` with the chosen tag. Those files are absent until an update succeeds, so a missing file always looks stale.
- On each bump, the updater quotes upstream GitHub or Codeberg release notes into the app `CHANGELOG.md` as blockquote lines starting with `> Upstream `. If the release body is short, it uses the matching section of `CHANGELOG.md`, `CHANGES.md`, `HISTORY.md`, or `NEWS.md` at that tag. `python3 scripts/update-upstream-version.py --notes` backfills the current recorded version. pgAdmin, PostgreSQL, and Semaphore have no upstream release notes or changelog file, so they keep a one-line upgrade entry.
- Trivy still scans images after builds and weekly, but it no longer uploads SARIF to GitHub code scanning. Upstream CVEs were dismissed as won't fix; uploading the same results reopened them.
- `main` requires a verified commit signature. A local `git commit` from `github-actions[bot]` is unsigned and is rejected. Renovate (`renovate.json`, Actions only — no `renovate.json5`) owns GitHub Actions dependency PRs; it must not bump add-on image pins in `build.yaml`/`Dockerfile` because that skips `config.yaml` version and CHANGELOG. App upstream bumps stay on `.github/workflows/track-upstream.yml` / `scripts/update-upstream-version.py` (CHANGELOG quotes, signed commits, build dispatch).
- The Acme.sh add-on has no `upstream_repo`. It follows `ghcr.io/acmesh-official/acme.sh:latest` and runs `acme.sh --upgrade` on start and before each renewal, so the version updater does not pin a release. Certificate stores live at `/ssl/acme.sh/<domain>` with `/data/acme.sh/<domain>` as a symlink; it does not write `/ssl/<domain>/`. `env_vars` entries can be marked `secret` so values stay masked and out of logs.
- Technitium polls for file changes (`DOTNET_USE_POLLING_FILE_WATCHER=1`) and disables config reload on change, because Home Assistant OS shares `fs.inotify.max_user_instances` across add-ons. It uses workstation GC to keep the heap smaller.
- Prefer Supervisor `app_config` / host `app_configs/` over legacy `addon_config`/`addon_configs/`; wrappers one-time copy then delete legacy host trees (acme-sh, alloy, linkding, pgadmin, forgejo, Traefik). Legacy migrations must be idempotent (shared `migrate-legacy-app-config.sh`): no-op when the destination already has content or the legacy tree is gone — re-running on every start must not fail the app. The Traefik add-on mounts `homeassistant_config` at `/homeassistant` (not `/config`); custom static `providers.file.directory` must be `/homeassistant/traefik/dynamic/` (not `/config/traefik/dynamic/`; host path next to `configuration.yaml`). Traefik Manager and Traefik Manager Agent HA wrappers must export options then `exec` the upstream image entrypoints (`/app/scripts/docker-entrypoint.sh` with `/app/gunicorn.conf.py` for Manager; `/usr/local/bin/docker-entrypoint.sh tma` for Agent). The Agent exposes API port 8090 only (no Web UI). Upstream `CERT_RESOLVER` defaults to `cloudflare`.
- n8n workflow files for this stack live under `n8n/` in this repo. `dns-ip-list-chunker` (formerly `unifi-blocklist-chunker`) is the HA wrapper for the DNS/IP list chunker. `unifi-notifi` is the first-party Alarm Manager → Slack threat enricher; `n8n/unifi-threat-enricher` is the matching n8n workflow (use one or the other on a given alarm). Pocket ID is a thin upstream wrapper with direct `webui` on port 1411 (no HA Ingress); SMTP options only apply when `UI_CONFIG_DISABLED` is on, which the wrapper enables when any SMTP field is set. Homarr OIDC against Pocket ID needs `AUTH_OIDC_TOKEN_ENDPOINT_AUTH_METHOD=client_secret_post` (Pocket ID rejects Homarr's default `client_secret_basic`) and `BASE_URL` set to the public origin when reverse-proxied. `otlp-collector` ships a default config that exports Home Assistant host/container metrics, logs, and traces to a user-chosen OTLP endpoint, with optional `config_yaml` override.

> # We just shipped Homarr 2.0.0, the biggest homarr update ever
> # The big two: Custom Widgets and Workshop
>
> Custom Widgets v2 lets you build almost any widgets. Build it with JSX, define the options it has and add it to your instance. Write them yourself, or describe what you want and generate it. Custom widgets can re-use existing integrations without the need to enter credentials or support any API endpoint.
>
> Workshop pairs nicely with it: You can publish, vote on, explore and install widgets & custom CSS other users have shared. We ask that you test and validate your slop before submitting it, or other users will downvote you into oblivion
>
> Board editing has been rebuilt
>
> New drag and drop system based on dnd-kit, doesn't suck anymore Containers replace Groups and dynamic sections. We added sidebars back, they stay put while the board scrolls.
>
> # Why "the front door to your homelab"?
>
> Homarr already connects to your services through integrations. In v2, Integration Requests let other Homarr features reuse those connections without exposing the underlying service credentials.
>
> For example, a Custom Widget can request data from Sonarr through Homarr. Homarr checks that the request is allowed, makes the request using the credentials stored on your instance, and returns the result.  The same system is available over HTTP and, optionally, MCP. This means you can give an MCP-compatible client access to selected Homarr capabilities without giving that client the API keys for every service in your homelab nor direct network access to those services.
>
> # TLDR, if an app's  api can do it, you are now able to do it through Homarr, even when there is no button for it, with a custom widget, an api call or the mcp.
>

> * Instance branding: name, logo, favicon, colors and global CSS can be setup instance-wide.
> * Statistics widget combines metrics from different services in one grid, compatible with every integration

> * Docker and Podman support with multiple endpoints, assisted setup and docker labels
> * Performance: startup work runs in parallel, heavy screens load on demand, duplicate requests share cache And a\*\* very\*\* long list of bug fixes

  quietly switched the registry from the private Forgejo registry to a
  public GHCR path, downgraded the required Home Assistant version, and
  flipped `init` to `true` (which fights Homarr's own entrypoint). All
  three are reverted back to the working configuration.
- CI/registry: image now builds via **GitHub Actions** and publishes to
  **GHCR** (`ghcr.io/charlestephen/hassio-addons-homarr-{arch}`), replacing
  the Forgejo self-hosted runner / private registry pipeline. The image is
  now public, so no registry credentials are needed to install this app.

- Docs: renamed "add-on" → "app" throughout (branding only, no
  functional change).

## 1.70.0-1

- Fix: database could not be created when running as a non-root user. The
  wrapper now runs as root before Homarr drops privileges and chowns both
  HA's `/data` and Homarr's `/appdata` volume to the configured `PUID:PGID`,
  so any user/group set in the options works. Homarr's own entrypoint only
  chowns `/app` and nginx dirs, which left the data volumes root-owned.

## 1.70.0

Initial release.

- Thin Home Assistant wrapper around the official
  `ghcr.io/homarr-labs/homarr:1.70.0` image (multi-arch: `aarch64`, `amd64`).
- Homarr's own entrypoint (redis + nginx + Next.js) is preserved; the app
  only injects configuration as environment variables.
- SQLite database is persisted to the app `/data` volume
  (`DB_URL=/data/db/db.sqlite`) so it survives updates and restarts.
- `SECRET_ENCRYPTION_KEY` is auto-generated once and persisted to `/data`
  when left blank, so encrypted secrets remain readable across restarts.
- Full environment-variable surface exposed as app options, including:
  - Authentication: `AUTH_PROVIDERS`, session expiry, cookie prefix, logout URL.
  - **OIDC/SSO**: issuer, client id/secret/name, scope overwrite, groups
    attribute, auto-login, local group management, force-userinfo, account
    linking, token endpoint auth method, name attribute overwrite.
  - **LDAP**: URI, base, bind DN/password, attribute and group mappings,
    search scope, extra filter args.
  - Optional external database and external Redis.
  - Docker integration (remote hosts) and outbound proxy settings.
